Ricart-Agrawala Algorithm

Ricart-Agrawala (RA) Algorithm

Key Idea

No central leader. Each process multicasts its request to all others and waits for all to reply.

States

Each process Pi is in one of three states:

  • Released — not interested in CS
  • Wanted — waiting to enter CS
  • Held — currently in CS

Algorithm

enter() at Pi

On receiving Request <Tj, j> at Pi (i ≠ j)

Important — Priority Rule: (Ti, i) < (Tj, j) uses lexicographic ordering:

  • Compare Lamport timestamps first
  • Break ties by process ID
  • Smaller = higher priority = reply deferred

exit() at Pi

Execution Flow

Performance

Tip — Optimal Sync Delay: RA achieves 1 message delay for synchronization — the fastest possible. The exiting process sends replies directly to the next waiter.

Warning — High Bandwidth: 2(N-1) messages per CS entry is expensive at scale. Maekawa reduces this using voting sets.
